src/styles/buttons.css

概要

ボタンのスタイルです。design.md の Buttons が定める文法は ピル型の主ボタン・輪郭だけの副ボタン・小さな実務ボタンの 3つだけで、このファイルもそれに従います（加えてカード内用の .btn-pearl を派生として持ちます）。

特徴はホバー状態を定義しないことです。Apple のボタンは マウスを乗せても色が変わらず、押した瞬間だけ scale(0.95) で わずかに縮みます。タッチ操作にホバーが存在しないことを前提にした設計で、 マウスとタッチで挙動が食い違いません。

構成

名前種別説明
.btn基底クラス全ボタン共通の寸法・書体・押下アニメーション
.btn:active / :disabled / :hover状態押下で縮小、無効で淡色、ホバーは何もしない
.btn-primary修飾クラス青のフルピル。主要アクション
.btn-secondary修飾クラス青の輪郭だけのゴーストピル
.btn-utility修飾クラスナビ内の小さな実務ボタン
.nav .btn-utility文脈上書き黒背景では輪郭だけの淡色に
.btn-pearl修飾クラスカード内の控えめな第2アクション
.btn-rowクラス横並びのアクション群。狭い画面では全幅

コード解説

.btn {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  min-height: var(--touch-target);
  border: none;
  font-family: var(--font-text);
  font-size: var(--text-body-size);
  line-height: 1;
  letter-spacing: var(--tracking-body);
  text-decoration: none;
  cursor: pointer;
  transition: transform 0.12s ease-out;
}

inline-flex と中央揃えにより、<button> でも <a>（TanStack Router の <Link>）でも 同じ見た目になります。ボタンに見えるリンクとリンクに見えるボタンが 混在しても、寸法と文字位置が揃います。

font-family をわざわざ指定しているのは、フォーム要素が body のフォントを自動では継承せず、ブラウザ既定の フォントになってしまうためです。

min-height: var(--touch-target)（44px）で最小タップ領域を 保証します。line-height: 1 にしているのは、本文の 1.47 のままだと パディングと合算して意図より背が高くなるからです。 

.btn:active:not(:disabled) {
  transform: scale(0.95);
}

.btn:disabled {
  color: var(--ink-muted-48);
  cursor: not-allowed;
}

.btn:hover {
  text-decoration: none;
}

押下フィードバックは全種類共通で scale(0.95)。 :not(:disabled) を付けているので、無効化されたボタンを 押しても縮まず、「押せなかった」ことが伝わります。

.btn:hover が text-decoration: none だけなのは、 base.css の a:hover が下線を付けてしまうのを 打ち消すためです。ホバーで見た目を変えないという design.md の方針を守るために、あえて「何も起きない」を明示しています。 

/* 主要アクション。青のフルピル＝「押せる」の合図 */
.btn-primary {
  padding: 11px 22px;
  border-radius: var(--radius-pill);
  background: var(--color-primary);
  color: var(--color-on-primary);
}

.btn-primary:disabled {
  background: var(--hairline);
}

完全な角丸（--radius-pill = 9999px）の青いピルが、 このシステムで最も強い「押せる」の合図です。1画面に1つだけ置くのが原則で、 「保存する」「車両を追加」などがこれにあたります。

無効時は背景を淡いグレー（--hairline）に落とします。 基底クラス側で文字色も --ink-muted-48 になるため、 グレー地にグレー文字という控えめな見た目になり、青と明確に区別できます。 

/* 2つ目のCTA。青の輪郭だけのゴーストピル */
.btn-secondary {
  padding: 11px 22px;
  border: 1px solid var(--color-primary);
  border-radius: var(--radius-pill);
  background: transparent;
  color: var(--color-primary);
}

主ボタンと同じ形・同じ色でありながら、塗りを抜くことで格を1段下げます。 第2のアクセント色を足さずに優先度の差を作る、というのが design.md の 考え方です（「押せる」の信号はすべてこの青ひとつ）。 

/* ナビ内の小さな実務アクション（ログアウト等） */
.btn-utility {
  min-height: 32px;
  padding: 8px 15px;
  border-radius: var(--radius-sm);
  background: var(--ink);
  color: var(--body-on-dark);
  font-size: var(--text-caption-size);
  letter-spacing: var(--tracking-caption);
}

ピルではなく 8px の角丸の小さな箱で、ログアウトのような 事務的な操作に使います。min-height を 32px に落として 44px の原則から外れていますが、これは design.md が 「グローバルナビのユーティリティリンクは、精密なデスクトップ操作である ことを理由に意図的に小さい」と明記している箇所に沿ったものです。 

/* 黒背景のナビ上では ink が沈むため、輪郭だけの淡色にする */
.nav .btn-utility {
  background: transparent;
  border: 1px solid rgba(255, 255, 255, 0.4);
}

--ink（#1d1d1f）の箱を純黒のナビに置くと、色が近すぎて ボタンの輪郭が消えます。そこでナビの中でだけ塗りを抜き、 半透明の白い枠に差し替えます。.nav を前置した 文脈依存の上書きなので、新しいクラス名を増やさずに 済みます。 

/* カード内の控えめな第2アクション */
.btn-pearl {
  min-height: 36px;
  padding: 8px 14px;
  border: 3px solid var(--divider-soft);
  border-radius: var(--radius-md);
  background: var(--surface-pearl);
  color: var(--ink-muted-80);
  font-size: var(--text-caption-size);
  letter-spacing: var(--tracking-caption);
}

車両カードの「編集」「記録を見る」など、カード内に複数並ぶ操作用です。 枠線が 3px と太いのは、design.md が divider-soft を「硬い線というよりリングシャドウとして働く」 トーンと位置づけているためで、極薄の色を厚く敷くことで 影を使わずに柔らかい縁取りを作っています。 

/* 横並びのアクション群 */
.btn-row {
  display: flex;
  flex-wrap: wrap;
  gap: var(--space-sm);
  align-items: center;
}

@media (max-width: 480px) {
  .btn-row > .btn {
    flex: 1 1 100%;
  }
}

複数ボタンを横に並べる入れ物です。flex-wrap: wrap により 入りきらなければ自然に折り返します。

480px 以下では flex: 1 1 100% で各ボタンを全幅にし、 縦積みにします。狭い画面で小さなボタンが肩を並べると押し間違いが 起きやすいため、1行1操作にして誤タップを防ぎます。
