概要

日付を日本語の画面表示用の文字列に変換する専用ファイルです。 「2026年9月6日(日)」のような曜日付きの表示と、「9/6」のような一覧向けの短い表示の 2 種類を提供します。

lib/date ディレクトリの中で唯一 date-fns を使ってよいファイルです。 他のファイル（date-string.ts、add-months.ts）は Cloudflare Workers（UTC）と利用者の端末（JST）のタイムゾーン差を避けるため、 意図的に Date オブジェクトを使わず文字列と整数だけで計算しています。 このファイルがやっているのは日付の「計算」ではなく「表示への変換」であり、 曜日名を求めるには標準ライブラリの厚みが要るため、ここだけ例外的に date-fns を使います。

このファイルの関数を計算に使ってはいけません。 日付の前後比較や加減算は、必ず date-string.ts や add-months.ts の関数を使います。

構成

名前種別説明

コード解説

export function formatJa(date: DateString): string {
  return format(parseISO(date), 'yyyy年M月d日(E)', { locale: ja })
}

parseISO で DateString（"2026-09-06" の形式）を Date オブジェクトに変換し、date-fns の format で 日本語の書式に整形します。書式指定子 'yyyy年M月d日(E)' の M・d（大文字小文字を区別）はゼロ埋めしない月・日を意味し、 (E) が曜日（日本語ロケールなら「日」「月」など1文字）に対応します。

なぜ「計算」ではなく「変換」だから安全なのか。 YYYY-MM-DD のような日付のみの文字列を parseISO（内部的には Date のコンストラクタと同様の解釈）に渡すと、 UTC の深夜0時として解釈されます。ここから format が年・月・日・曜日を取り出す際も一貫して UTC 基準の値を読むため、 実行環境（Workers の UTC でも開発機の JST でも）に関わらず、 入力した日付文字列どおりの年月日・曜日が得られます。 タイムゾーンのズレが問題になるのは「今この瞬間が何月何日か」を求める場面 （jst.ts の役割）であって、「すでに確定した日付文字列を人間向けに書き直す」 だけのこの関数には影響しません。 

export function formatJaShort(date: DateString): string {
  return format(parseISO(date), 'M/d')
}

整備記録の一覧のように、日付を何行も縦に並べる画面では 曜日や年まで出すと画面が窮屈になります。formatJa より短い 「9/6」形式だけを返す、一覧表示専用の関数です。
