概要

整備記録を更新するサーバー関数です。整備記録の編集ページ （_authed.vehicles.$vehicleId.records.$recordId.edit.tsx）から、 「どの記録を（id）」「どんな内容に（recordSchema で 検証済みの入力）」更新するかを受け取ります。

create.ts と同じ理由で record フィールドにネストさせて スキーマを合成しています。vehicle_id は更新対象に含めていません。 記録を別の車両へ付け替える操作はこのアプリの仕様に存在しないためです。

コード解説

const updateRecordSchema = recordIdSchema.extend({ record: recordSchema })

create.ts の createRecordSchema と対称的な構成です。 こちらは「どの記録を」を表す recordIdSchema（{ id }）に、 「どんな内容に」を表す record フィールドを足しています。 

export async function updateRecordHandler(
  input: UpdateRecordInput,
  deps: UpdateRecordDeps,
): Promise<MaintenanceRecordRow | null> {
  const { data, error } = await deps.supabase
    .from('maintenance_records')
    .update({
      performed_on: input.record.performedOn,
      work_type: input.record.workType,
      work_type_other: input.record.workTypeOther,
      odometer_km: input.record.odometerKm,
      part_detail: input.record.partDetail,
      note: input.record.note,
    })
    .eq('id', input.id)
    .select()
    .maybeSingle()
  if (error) {
    throw new Error(error.message)
  }
  return data
}

.maybeSingle() を使い、存在しない記録・他人の記録（RLSがブロック）を 区別せず null を返します。vehicles/server/update.ts と同じ理由で、 「この ID は他人が使っている」という情報を漏らさないためです。 

export const updateRecordFn = createServerFn({ method: 'POST' })
  .validator(updateRecordSchema)
  .handler(({ data }) => updateRecordHandler(data, { supabase: createSupabaseServerClient() }))

呼び出し側は updateRecordFn({ data: { id: record.id, record: input } }) という形で呼びます。
