work-types.ts

src/features/maintenance/lib/work-types.ts

概要

整備記録の「作業内容」プリセット（エンジンオイル、オイルエレメント、タイヤ、 ブレーキパッド、バッテリー、車検、その他）を定義するファイルです。 このプリセットは DB の work_type 列にそのまま保存する値なので、 画面・スキーマ検証・DBのどこから見ても同じ値の集合を参照できるよう、 ここで一度だけ定義しています。

構成

名前種別説明
WORK_TYPESconst（export）作業内容プリセット7種類の配列
WorkTypetype（export）WORK_TYPES の要素から推論した文字列リテラル型
workTypeLabelfunction（export）プリセット値から日本語ラベルを返す
isOtherWorkTypefunction（export）「その他」が選ばれているかを判定する

コード解説

export const WORK_TYPES = [
  'engine_oil',
  'oil_element',
  'tire',
  'brake_pad',
  'battery',
  'shaken',
  'other',
] as const

export type WorkType = (typeof WORK_TYPES)[number]

値の一覧を配列リテラルとして定義し、そこから型を逆算しています。 as const を付けることで配列の各要素が広い string ではなく個々のリテラル型として扱われ、(typeof WORK_TYPES)[number] で「配列の要素のどれか」というユニオン型を取り出せます。値の一覧と型の 2箇所を手で同期させる必要が無くなるのが利点です。

この配列はそのまま record-schema.ts の z.enum(WORK_TYPES, ...) にも渡され、Zod の検証対象にもなります。 

export function workTypeLabel(type: WorkType): string {
  switch (type) {
    case 'engine_oil':
      return 'エンジンオイル'
    case 'oil_element':
      return 'オイルエレメント'
    case 'tire':
      return 'タイヤ'
    case 'brake_pad':
      return 'ブレーキパッド'
    case 'battery':
      return 'バッテリー'
    case 'shaken':
      return '車検'
    case 'other':
      return 'その他'
  }
}

画面表示用の日本語ラベルに変換するだけの関数です。switch が WorkType の全パターンを網羅しているため、将来 WORK_TYPES に値を追加した際は、この switch の 分岐を足し忘れると TypeScript が「網羅していない」というエラーで 教えてくれます。 

export function isOtherWorkType(type: WorkType): boolean {
  return type === 'other'
}

「その他」が選ばれているかどうかを判定するだけの小さな関数ですが、 独立させているのには理由があります。「その他」を選んだときだけ 自由入力欄（work_type_other）が必須になるという業務ルールが あり、このルールは record-schema.ts の検証、 フォームコンポーネントの表示切り替えなど複数箇所から参照されます。 type === 'other' という比較を各所に直接書くのではなく、 名前の付いた関数にすることで「なぜその判定をしているか」がコードだけで 伝わるようにしています。
