概要

整備記録（日付・作業内容・走行距離・部品/型式・備考）の登録・編集フォーム 入力を検証する Zod スキーマです。vehicle-schema.ts と同様、 「全書き込みはサーバー関数の入口で Zod 検証する」というプロジェクト方針に 沿っています。

このファイルでいちばん重要なのは、単純なフィールド単位の検証では表現できない 「作業内容が『その他』のときだけ自由入力欄が必須になる」というルールです。 これは .refine() によるオブジェクト全体の相互検証で実現しています。

コード解説

export const recordSchema = z
  .object({
    performedOn: dateStringSchema,
    workType: z.enum(WORK_TYPES, { error: '作業内容を選択してください' }),
    workTypeOther: z
      .string()
      .trim()
      .max(WORK_TYPE_OTHER_MAX_LENGTH, `作業内容は${WORK_TYPE_OTHER_MAX_LENGTH}文字以内で入力してください`)
      .default(''),
    odometerKm: z
      .number()
      .int('走行距離は整数で入力してください')
      .nonnegative('走行距離は0以上で入力してください')
      .nullable()
      .default(null),
    partDetail: z
      .string()
      .trim()
      .max(PART_DETAIL_MAX_LENGTH, `部品/型式は${PART_DETAIL_MAX_LENGTH}文字以内で入力してください`)
      .default(''),
    note: z
      .string()
      .trim()
      .max(NOTE_MAX_LENGTH, `備考は${NOTE_MAX_LENGTH}文字以内で入力してください`)
      .default(''),
  })

フィールドごとの検証です。

performedOn — src/lib/date/date-string-schema.ts の共有スキーマをそのまま使い、vehicle-schema.ts と同じ基準で 日付を検証します。

workType — work-types.ts の WORK_TYPES（7つのプリセット）から選ばれた値だけを許可します。

odometerKm — 整数かつ0以上。.nullable().default(null) により、フォームで未入力（undefined）でも「不明」を意味する null として保存されます。前回記録との比較は odometer.ts の役割で、ここでは単体の値としての妥当性だけを見ます。

workTypeOther / partDetail / note — いずれも .trim() 後に文字数上限、未入力時は空文字が既定値です。 

  .refine((data) => !isOtherWorkType(data.workType) || data.workTypeOther.length > 0, {
    message: '作業内容が「その他」の場合は内容を入力してください',
    path: ['workTypeOther'],
  })

「workType が other」と「workTypeOther が 空でない」という2フィールドにまたがる条件なので、単一フィールドの .min() などでは表現できません。オブジェクト全体を検証する .refine() を使い、条件式は !isOtherWorkType(...) || workTypeOther.length > 0 —「その他でない、または、その他だが入力済み」という論理積の否定形です。 work-types.ts の isOtherWorkType をそのまま使うことで、 「その他かどうか」の判定基準がこのファイルとプリセット定義側でズレません。

path: ['workTypeOther'] を指定しているのは、エラーメッセージを フォームの workTypeOther 欄の下に表示できるようにするためです。 指定しないとエラーがオブジェクト全体（path: []）に紐づき、 どのフィールドが悪いのか画面側で判別しづらくなります。
