概要

車両の登録・編集フォームから送られてくる入力を検証する Zod スキーマです。 「全書き込みはサーバー関数の入口で Zod 検証する」というプロジェクト方針 （CLAUDE.md）に沿って、車両まわりの入力検証をこの1ファイルに 集約しています。

使っている Zod は 4系で、z.string().email() のような書き方が 廃止されるなど記法が変わっているため、実際にインストールされているバージョンの 挙動をコードで確認しながら実装しています。

コード解説

const dateStringSchema = z.string().transform((value, ctx) => {
  if (!isDateString(value)) {
    ctx.addIssue({ code: 'custom', message: '日付は YYYY-MM-DD 形式で、実在する日付を指定してください' })
    return z.NEVER
  }
  return value
})

満了日の検証に使う内部スキーマです。ただの正規表現ではなく、 src/lib/date/date-string.ts の isDateString を そのまま呼び出しています。これにより「形式は YYYY-MM-DD だが 2026-02-30 のように実在しない日付」も、日付ロジック側と まったく同じ基準ではじけます。判定ルールを2箇所に別々に書いて ズレるリスクを避けるための共有です。

.refine()ではなく.transform() を使っているのは、 検証に通った後の値を DateString（ブランド型）として 扱いたいためです。isDateString は TypeScript の型ガード （value is DateString）なので、if 文を通過した後の return value は自動的に DateString 型として 推論されます。検証に失敗した場合は ctx.addIssue でエラーを 積んだ上で z.NEVER を返し、Zod にこの入力が無効であることを 伝えます。 

export const vehicleSchema = z.object({
  name: z
    .string()
    .trim()
    .min(1, '車種名を入力してください')
    .max(NAME_MAX_LENGTH, `車種名は${NAME_MAX_LENGTH}文字以内で入力してください`),
  vehicleType: z.enum(['car', 'motorcycle'], { error: '車両区分を選択してください' }),
  shakenExpiryDate: dateStringSchema.nullable(),
  note: z
    .string()
    .trim()
    .max(NOTE_MAX_LENGTH, `備考は${NOTE_MAX_LENGTH}文字以内で入力してください`)
    .default(''),
})

4つのフィールドを検証します。

name — .trim() で前後の空白を 落としてから .min(1) で必須チェックするため、 空白だけの入力（" "）も未入力として弾かれます。 上限は50文字。

vehicleType — 'car' / 'motorcycle' の2値のみ許可する列挙。vehicle-type.ts の VehicleType 型と対応しています。

shakenExpiryDate — 上で定義した dateStringSchema を .nullable() でラップしています。 null は「250cc以下のバイクなど車検制度の対象外」を表す 正常値であり、エラーにはしません（判定は shaken-required.ts の役割）。

note — 備考欄。.default('') により、フォームで備考が未入力（undefined）でも常に文字列 '' として扱われ、以降のコードで null や undefined の分岐を書かずに済みます。上限は1000文字。 

export type VehicleInput = z.infer<typeof vehicleSchema>

スキーマから型を逆算しています。フィールドの型定義をスキーマとTypeScriptの 型定義の2箇所に書くと将来どちらかが更新漏れでズレるため、 スキーマを唯一の情報源（single source of truth）にしています。
