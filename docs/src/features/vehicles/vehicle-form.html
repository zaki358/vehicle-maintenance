src/features/vehicles/vehicle-form.tsx

概要

車両の新規登録（routes/_authed.vehicles.new.tsx）と編集 （routes/_authed.vehicles.$vehicleId.edit.tsx）の両方で共用する フォームコンポーネントです。React・ルーティング・Supabase に依存するため lib/ 配下ではなく features/vehicles/ 直下に置いています （eslint.config.js の境界ルールにより lib/ は React import を禁止されている）。

2つのページで見た目と検証ロジックが完全に同じフォームを別々に実装すると 片方だけ直し忘れる事故が起きやすいため、1つのコンポーネントに切り出しました。 新規登録では initialValues を渡さず全項目を空欄から始め、 編集では現在の値を渡します。

構成

名前種別説明
VehicleFormResulttype（export）onSubmit が返す結果の型
VehicleFormfunction（export・コンポーネント）車両の登録・編集フォーム本体

コード解説

interface VehicleFormProps {
  initialValues?: VehicleInput
  submitLabel: string
  onSubmit: (input: VehicleInput) => Promise<VehicleFormResult>
}

フォーム自身は「検証済みの入力を onSubmit に渡す」ところまでが 責務で、実際にサーバー関数（createVehicleFn / updateVehicleFn） を呼ぶのは呼び出し元のルートファイルです。これにより、このコンポーネントは 「新規登録なのか編集なのか」を一切知らずに済みます。 

const [shakenExpiryDate, setShakenExpiryDate] = useState(initialValues?.shakenExpiryDate ?? '')

車検満了日は「250cc以下のバイクなど、そもそも車検制度の対象外」という 車両があるため任意入力です。<input type="date"> は 未入力だと空文字列を返しますが、vehicleSchema の shakenExpiryDate は「実在する日付文字列 or null」しか 受け付けません（空文字列は弾かれる）。この状態変数はUI都合の string のまま持ち、送信時に変換します。 

const parsed = vehicleSchema.safeParse({
  name,
  vehicleType,
  shakenExpiryDate: shakenExpiryDate === '' ? null : shakenExpiryDate,
  note,
})
if (!parsed.success) {
  setError(parsed.error.issues[0]?.message ?? '入力内容を確認してください')
  return
}

送信時に空文字列を null へ変換してから、vehicle-schema.ts と全く同じ vehicleSchema でクライアント側の検証をします。 login.tsx と同じパターンで、最初のエラーメッセージ1件だけを 画面に表示するシンプルな方式です（このクライアント側検証はUXのためであり、 実際のセキュリティ境界はサーバー関数側の同じスキーマによる再検証です）。 

const result = await onSubmit(parsed.data)
if (!result.success) {
  setError(result.error)
}

検証を通った入力（DateString | null に変換済みの VehicleInput）を onSubmit に渡します。呼び出し元が サーバー関数の呼び出しに失敗した場合は { success: false, error } を返す約束にしており、その場合はフォーム側でエラーメッセージを表示します。
