概要

車両を新規作成するサーバー関数です。routes/_authed.vehicles.new.tsx の登録フォームから呼ばれます。フォーム入力（キャメルケース）をDBの列名 （スネークケース）へ詰め替える変換もこのファイルの責務です。

コード解説

export async function createVehicleHandler(input: VehicleInput, deps: CreateVehicleDeps): Promise<VehicleRow> {
  const { data, error } = await deps.supabase
    .from('vehicles')
    .insert({
      name: input.name,
      vehicle_type: input.vehicleType,
      shaken_expiry_date: input.shakenExpiryDate,
      note: input.note,
    })
    .select()
    .single()
  if (error) {
    throw new Error(error.message)
  }
  return data
}

insert するオブジェクトに user_id を含めていないのが 意図的な設計です。vehicles.user_id は マイグレーションで default auth.uid() になっているため、 クライアントが user_id を指定できる余地そのものを無くしています （もし指定できてしまうと、他人の user_id を詐称して なりすまし登録される脆弱性になり得ます）。.insert(...).select().single() は「挿入した行をそのまま返す」ためのPostgRESTの定番の書き方です。 

export const createVehicleFn = createServerFn({ method: 'POST' })
  .validator(vehicleSchema)
  .handler(({ data }) => createVehicleHandler(data, { supabase: createSupabaseServerClient() }))

「全書き込みはサーバー関数の入口で Zod 検証する」という プロジェクト方針どおり、フォームの生入力を vehicleSchema （vehicle-schema.ts）でもう一度検証してから DB に渡します。 クライアント側の検証（vehicle-form.tsx）はUXのためであり、 ここでの検証が実際のセキュリティ境界です。
