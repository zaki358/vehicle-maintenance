概要

車検完了を記録するためのフォームコンポーネントです。 vehicle-form.tsx / record-form.tsx と同じく 素のHTML要素＋Zodスキーマで実装しており、UIライブラリは使っていません。 受検日・有効期間（2年/3年）・新しい満了日・走行距離・部品/型式・備考を入力し、 送信すると complete-shaken-schema.ts で検証してから 呼び出し元（ルート）の onSubmit に渡します。

このフォームの中心は「新しい満了日」欄です。renewal.ts の computeNextShakenExpiry（制度どおりの繰り越しルール）で自動計算した値を 表示しつつ、利用者が直接編集もできます（要件「計算結果を表示し手動修正も可」）。

const [performedOn, setPerformedOn] = useState('')
const [years, setYears] = useState<ShakenValidYears>(2)
const [newExpiryDateOverride, setNewExpiryDateOverride] = useState<string | null>(null)
...
const computedExpiry = isDateString(performedOn)
  ? computeNextShakenExpiry({ completedOn: performedOn, currentExpiry, years })
  : null
const newExpiryDate = newExpiryDateOverride ?? computedExpiry ?? ''

「新しい満了日」欄の値は、newExpiryDateOverride（利用者が直接編集した値。 未編集なら null）を最優先し、無ければ自動計算値 computedExpiry を使う、という優先順位の組み立てです。 これにより「表示はするが上書きもできる」という要件をシンプルな ?? の連鎖だけで実現しています。

useEffect を使わずに済んでいるのもポイントです。 「受検日・有効期間が変わったら手動修正をリセットする」という挙動は、 下記の handlePerformedOnChange / handleYearsChange の中で setNewExpiryDateOverride(null) を直接呼ぶだけで 表現できています（変更の起点が自分自身の onChange の中にあるため）。 

function handlePerformedOnChange(value: string) {
  setPerformedOn(value)
  setNewExpiryDateOverride(null)
}

function handleYearsChange(value: string) {
  setYears(Number(value) as ShakenValidYears)
  setNewExpiryDateOverride(null)
}

受検日または有効期間を変更するたびに、手動修正した「新しい満了日」を 破棄して自動計算に戻します。これをしないと、「古い受検日に対して 手動で直した満了日」が新しい受検日にそのまま残ってしまい、 実際の制度上の満了日とズレたまま気づかれない危険があります。 

const parsed = completeShakenSchema.safeParse({
  performedOn,
  newExpiryDate,
  odometerKm: odometerKm === '' ? null : Number(odometerKm),
  partDetail,
  note,
})

送信処理自体は vehicle-form.tsx / record-form.tsx と まったく同じ形です。safeParse の結果が失敗なら最初のエラーメッセージを role="alert" の要素に表示し、成功なら onSubmit （呼び出し元のルートが渡す、サーバー関数呼び出しのラッパー）を呼びます。
