概要

車検完了フォームの入力を検証する Zod スキーマです。受検日・新しい満了日・ 走行距離・部品/型式・備考の5項目を持ち、整備記録の登録フォーム用 maintenance/lib/record-schema.ts と似ていますが、 「作業内容（workType）」を持たない点が異なります （車検完了は常に work_type = 'shaken' で固定のため）。

「新しい満了日」を検証はしても、受検日との前後関係までは強制しない設計です。 この値は renewal.ts の computeNextShakenExpiry が 自動計算した提案値であり、利用者が画面上で手動修正できる仕様 （要件「計算結果を表示し手動修正も可」）のため、業務ルールをここで サーバー側から強制すると手動修正そのものを塞いでしまいます。

構成

名前種別説明

コード解説

export const completeShakenSchema = z.object({
  performedOn: dateStringSchema,
  newExpiryDate: dateStringSchema,
  odometerKm: z
    .number()
    .int('走行距離は整数で入力してください')
    .nonnegative('走行距離は0以上で入力してください')
    .nullable()
    .default(null),
  partDetail: z.string().trim().max(PART_DETAIL_MAX_LENGTH, ...).default(''),
  note: z.string().trim().max(NOTE_MAX_LENGTH, ...).default(''),
})

performedOn（受検日）と newExpiryDate（新しい満了日）は、 どちらも共有スキーマ lib/date/date-string-schema.ts の dateStringSchema を使い、「実在する YYYY-MM-DD か」だけを検証します。

odometerKm・partDetail・note は record-schema.ts の同名フィールドと検証ルール（整数・0以上・最大文字数・trim）が 同一です。異なるテーブル操作用のスキーマを意図的に分けているため、 定数（最大文字数）も含めてこのファイル内で完結させています （3〜4行程度の重複であれば、無理に共通化して2つの機能をカップリングさせない方針）。
