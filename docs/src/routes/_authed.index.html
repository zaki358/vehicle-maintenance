概要

_authed レイアウトの「index」ルート、つまり URL / に対応するページです。ログインすると最終的に辿り着く場所。

これは仮の実装です。 本来のダッシュボード （車両一覧・車検アラート）は Phase 7 で作ります。このファイルは Phase 4（認証）の時点で「_authed ガードが正しく機能しているか」 「ログイン→ログアウトの導線が一通り動くか」をブラウザで実際に確認できる ようにするための最小限の仮実装で、Phase 7 で中身を丸ごと置き換えます。 これが無いと、認証フェーズの成果物をルートの入力欄まで見ることはできても、 実際にブラウザで最後まで動かして確認することができませんでした。

Route.useRouteContext() で、親の _authed.tsx の beforeLoad がセットした user をそのまま 受け取れます。この画面自身は一切セッションを取得し直しません — 認証チェックは既に beforeLoad の時点で完了しているため、 ここに来た時点で user は必ず存在します。 

async function handleLogout() {
  setLoggingOut(true)
  try {
    await logoutFn()
    await navigate({ to: '/login', replace: true })
  } finally {
    setLoggingOut(false)
  }
}

ログアウトはサーバー関数 logoutFn() を呼ぶだけです。 Cookie の削除は logout.ts 側（サーバー用クライアントの cookies.setAll）が自動的に行うため、ここでは 「呼んで、ログイン画面へ戻る」という2手順だけを書いています。
