概要

車検完了を記録するページです（URL: /vehicles/$vehicleId/shaken）。 features/shaken/complete-shaken-form.tsx（ShakenForm）を表示し、 送信されたらサーバー関数 completeShakenFn を呼びます。 車両情報は親レイアウトルート（_authed.vehicles.$vehicleId.tsx）が beforeLoad で取得済みの vehicle をそのまま使うため、 このルート自身はloaderを持ちません。

このページへのリンクは、車両詳細ページ（shakenRequired が真の場合のみ）と ダッシュボード（車検アラートが出ている車両のみ）の2箇所に置いています。 URLを直接叩けば満了日未設定の車両（250cc以下のバイク等）に対しても 到達できますが、そもそも「車検アラート・車検UIを一切出さない」という 要件はリンクの出し分けで満たしており、この画面自体を車両区分やRLSで さらにブロックする必要はないと判断しました。

コード解説

async function handleSubmit(input: CompleteShakenInput): Promise<ShakenFormResult> {
  try {
    await completeShakenFn({ data: { vehicleId: vehicle.id, shaken: input } })
    await navigate({ to: '/vehicles/$vehicleId', params: { vehicleId: vehicle.id } })
    return { success: true }
  } catch {
    return { success: false, error: '記録に失敗しました。時間をおいて再度お試しください。' }
  }
}

records/new.tsx（Phase 6）の handleSubmit と まったく同じ形です。サーバー関数の入力は { vehicleId, shaken: input } という2フィールド構成 （complete-shaken.tsの vehicleScopeSchema.extend({ shaken: ... }) に対応）。成功したら車両詳細へ戻り、失敗したらフォーム側の role="alert" に表示するメッセージを返します。 

<ShakenForm
  currentExpiry={vehicle.shaken_expiry_date ? toDateString(vehicle.shaken_expiry_date) : null}
  submitLabel="車検完了を記録"
  onSubmit={handleSubmit}
/>

currentExpiry に null を渡せるのがポイントです。 車両にまだ満了日が設定されていない（＝初めて車検情報を記録する）場合、 ShakenForm内部の computeNextShakenExpiry は 「新規登録」の分岐（受検日 + N年）で計算します。1つのフォームで 「初回登録」と「更新（繰り越し判定あり）」の両方を自然に扱えます。
