# Supabase セットアップ手順

このアプリのデータベースと認証を担う Supabase を用意します。
**アカウント作成とダッシュボード操作は Claude が代行できないため、あなたに実施していただきます。**

所要時間: 20 分程度。

> **この手順では Supabase プロジェクトを 2 つ作ります。**
> 開発用（試行錯誤する場所）と本番用（実際に使う場所）を分けるためです。
> 無料プランで 2 つまで作れます。Docker を入れずに安全に開発するための構成です。

---

## 1. アカウントを作る

1. https://supabase.com を開く
2. 右上の **Start your project** をクリック
3. GitHub アカウントまたはメールアドレスでサインアップ

無料プラン（Free）で十分です。利用者数人・データ量もごく小さいため、
課金が必要になることはまずありません。

---

## 2. プロジェクトを 2 つ作る

### なぜ 2 つ必要か

データベースの「テーブル定義」は、作りながら何度も直します。
本番が 1 つしか無いと、**あなたやお友達が実際に使い始めた後のデータに、
試行錯誤が直接当たってしまいます。**

開発用で固めてから本番に適用する流れにすれば、この事故が起きません。

### 2-1. 開発用プロジェクト

**New project** をクリックし、以下を入力します。

| 項目 | 入力値 |
|---|---|
| **Name** | `vehicle-maintenance-dev` |
| **Database Password** | 自動生成ボタンで生成 → **控える** |
| **Region** | **Northeast Asia (Tokyo)** |
| **Plan** | Free |

### 2-2. 本番用プロジェクト

もう一度 **New project** をクリックします。

| 項目 | 入力値 |
|---|---|
| **Name** | `vehicle-maintenance` |
| **Database Password** | 自動生成ボタンで生成 → **控える**（dev とは別のもの） |
| **Region** | **Northeast Asia (Tokyo)** |
| **Plan** | Free |

### 注意点

- **Database Password は再表示できません。** パスワードマネージャ等に保存してください
  （アプリの動作には使いませんが、DB に直接つなぐときに必要になります）
- **Region は必ず東京**。日本から使うアプリなので、ここを間違えると全ての通信が遅くなります
- **どちらがどちらか分かるように名前を付けてください。** 取り違えると本番データを消しかねません

プロジェクトの初期化にそれぞれ 1〜2 分かかります。

> **無料プランの注意**: 1 週間アクセスが無いとプロジェクトが一時停止します。
> ダッシュボードから再開できますが、開発用は放置すると止まることを覚えておいてください。

---

## 3. API キーを取得する（2 つ分）

各プロジェクトで、左サイドバー下部の **Project Settings**（歯車アイコン）
→ **API Keys** を開きます。

必要なのは次の 2 つです。**開発用と本番用の両方で取得してください。**

### 3-1. Project URL（画面上は「API URL」と表示されます）

`https://xxxxxxxxxxxx.supabase.co` の形式。
**Project Settings → Data API**（または `.../settings/api` ページ）にあります。
**「General」タブには載っていません。** 末尾に `/rest/v1/` が付いていたら、
そこは含めずベースURLだけを使ってください。

### 3-2. Publishable key

`sb_publishable_` で始まる長い文字列。**API Keys** 画面の一覧にあります。

> **旧「anon key」ではありません。**
> 2025年11月以降に作られたプロジェクトでは anon / service_role キーは発行されません。
> ネット上の古い記事は `VITE_SUPABASE_ANON_KEY` を使えと書いていますが、無視してください。

### この 2 つは Claude に共有して問題ありません

Project URL と publishable key は **ブラウザに配信される前提で設計された公開値**です。
アプリのフロントエンドに埋め込まれるため、隠す意味がありません。
データの安全性は RLS（行レベルセキュリティ）が担保します。

---

## 4. 公開サインアップを無効にする ⚠️ 重要

**これをやらないと、URL を知った誰でもアカウントを作れてしまいます。**

**本番用プロジェクト**で必ず実施してください（開発用もやっておくと安全です）。

1. 左サイドバー **Authentication** → **Sign In / Providers**
2. **Email** プロバイダを開く
3. **Allow new users to sign up** を **OFF** にする
4. 保存

利用者はあなたが招待スクリプトで個別に追加します（実装は Phase 4）。

### あわせて確認

同じ Email プロバイダの設定で **Confirm email** は **ON** のままにしてください。
招待メール経由でパスワードを設定する流れで使います。

---

## 5. Secret key（管理者キー）の扱い ⚠️ 重要

**API Keys** 画面には `sb_secret_` で始まるキーもあります。
これは **DB の全データに RLS を無視してアクセスできる管理者キー**です。

### 絶対にやってはいけないこと

- ❌ チャットに貼り付ける
- ❌ Git にコミットする
- ❌ `VITE_` を付けた環境変数に入れる（ブラウザに配信されます）
- ❌ Cloudflare Workers の環境変数に設定する

### 正しい置き場所

このアプリでは、招待スクリプト（あなたの PC でのみ動かす）だけがこのキーを使います。
Phase 4 で `scripts/.env` というファイルを作る手順を案内しますので、
**そのときにあなた自身がコピー＆ペーストしてください。**
このファイルは `.gitignore` 済みで、Git には絶対に載りません。

**Worker（本番環境）にはシークレットを 1 つも置かない設計**にしています。
本番のデータアクセスは publishable key ＋ ログインユーザーの JWT ＋ RLS だけで行います。

---

## 6. 完了したら Claude に伝えること

以下を教えてください。これで Phase 2（データベース構築）に進めます。

```
【開発用 vehicle-maintenance-dev】
Project URL: https://xxxxxxxxxxxx.supabase.co
Publishable key: sb_publishable_xxxxxxxxxxxxxxxxxxxx

【本番用 vehicle-maintenance】
Project URL: https://yyyyyyyyyyyy.supabase.co
Publishable key: sb_publishable_yyyyyyyyyyyyyyyyyyyy

公開サインアップ: 本番で無効にした
```

**secret key と Database Password は送らないでください。** 必要になったら手順を案内します。

---

## 補足: この後の開発の流れ

1. テーブル定義（マイグレーション）を書く
2. **開発用プロジェクト**に適用して動作とセキュリティ（RLS）を検証する
3. 問題なければ**本番用プロジェクト**に同じものを適用する

Supabase CLI（`npm install -D supabase` 済み）でこの流れを管理します。
本番へ適用するコマンドを実行する前には、必ず内容を説明して承認をいただきます。
