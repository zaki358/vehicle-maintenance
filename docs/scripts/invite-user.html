概要

公開サインアップを無効化しているこのアプリで、新しい利用者にアカウントを 使ってもらうための唯一の手段——オーナーが自分の PC のターミナルで直接実行する、 招待専用のスクリプトです。src/ 配下のアプリケーションコードとは 独立していて、Cloudflare Workers にはデプロイされません。

Claude はこのスクリプトを実行しません。 実行には SUPABASE_SECRET_KEY（service_role 相当の強力な権限を持つ シークレットキー）が必要で、これはプロジェクトの方針上 Claude が扱わない値 だからです。scripts/.env（.gitignore 対象）にこの値を置き、 オーナー自身が node scripts/invite-user.ts <メールアドレス> を実行します。

コード解説

const email = process.argv[2]
if (!email) {
  console.error('使い方: node scripts/invite-user.ts <招待するメールアドレス> [招待後の遷移先URL]')
  process.exitCode = 1
  return
}

このプロジェクトにはビルドツールを追加していないため、 tsx のような別ツールを入れず、Node.js が標準で持つ TypeScript ファイルの直接実行機能（Node 22 以降）で node scripts/invite-user.ts ... とそのまま実行できるようにしています。 

const projectLabel = supabaseUrl.includes(PRODUCTION_HOST) ? '本番' : '開発用'
console.log(`招待先プロジェクト: ${projectLabel}（${supabaseUrl}）`)

招待メールは実際に送信される、取り消しの効かない操作です。誤って 開発用プロジェクトに向けて実行してしまう（あるいはその逆）事故を防ぐため、 実行前に「今どちらのプロジェクトに向けて送ろうとしているか」を 必ず画面に表示します。scripts/tests/support/env.ts （RLS 統合テスト）が本番プロジェクトへの実行を例外で強制的に止めるのに対し、 こちらは意図的にブロックしません — 招待は最終的に本番プロジェクトへ 送ることが目的の操作であるため、止めるのではなく「見える化」する設計です。 

const { data, error } = await admin.auth.admin.inviteUserByEmail(email, { redirectTo })

supabase.auth.admin.inviteUserByEmail() は PKCE に対応していません （招待する側＝オーナーのブラウザと、リンクを踏む側＝招待された利用者の ブラウザが異なるため、同一ブラウザ内でのコード検証を前提とする PKCE の 安全性を担保できないと Supabase 公式ドキュメントが明記しています）。 そのため招待メールのリンクは #access_token=...&type=invite というハッシュフラグメント形式になり、routes/set-password.tsx のブラウザ用クライアントがこれを自動検出してセッションを確立します。

redirectTo は Supabase ダッシュボードの Authentication → URL Configuration → Redirect URLs に事前に登録されている URL でなければ、リンクを踏んでもそこへ遷移しません。 このスクリプトはその設定を確認する手段を持たないため、実行前に コンソールへ遷移先 URL を出力し、オーナー自身がダッシュボードの設定と 見比べられるようにしています。
